> **Cleared by [T-0-017](../tickets/T-0-017-design-system-conformance.md).** This file is the
> historical record of what was wrong on 2026-08-19 and why. Every numbered item below was
> fixed on `t/T-0-017-design-system-conformance`, except the three carve-outs the ticket
> names in its Scope → Out and records in [UNFINISHED-AUDIT.md](../tickets/UNFINISHED-AUDIT.md).

Audit only. No code was changed.

Scope: every file in `vite/src/pages` and `vite/src/components`, plus
`vite/src/index.css`, `vite/tailwind.config.js`, and `vite/index.html` where a page
rule depends on them.

Rulebook: `CLAUDE.md` → "Design system (do not deviate)".
Supporting: doc 12c (brand), doc 16 (theming), design-principles.

Worst first. Work top to bottom.

1. **`vite/src/index.css:50-57`** — `--option-1` … `--option-8` are declared in
   `:root` only. `:root.dark` (line 60) redefines nothing. In dark mode every
   select/status chip keeps a pale pastel fill and draws `--text` (`#e7eaf0`, near
   white) on top of it. Contrast is roughly 1.2:1. The text is invisible.
   **Breaks:** "Dark mode is not optional. No screen ships until it is correct in
   both themes." Also doc 16's one-token-layer rule.
   **Fix:** add eight dark values for `--option-1…8` inside `:root.dark`.
   **Effort:** S

2. **`vite/src/components/ui/input.tsx:8`, `vite/src/components/ui/select.tsx:17`,
   `vite/src/components/ui/date-picker.tsx:122`** — every text field, select
   trigger, and date picker is `h-9` (36px) while `Button` is `h-8` (32px). Any row
   with a field next to a button is misaligned by 4px, everywhere in the app.
   **Breaks:** "One control height: `h-8` (32px). Buttons, inputs, selects, date
   pickers, toolbar controls, search boxes. No exceptions."
   **Fix:** change `h-9` to `h-8` in all three primitives, then delete the
   per-call-site `h-8` and `h-9` overrides listed in items 3 and 34.
   **Effort:** M

3. **`vite/src/pages/settings/Members_InviteForm.tsx:80,92,112`** — `h-9` is forced

   **Effort:** S

7. **`vite/src/lib/theme.ts:3-17`, `vite/src/components/UserMenu.tsx:73-82`** — the
   theme is a two-state light/dark toggle. There is no "System" option, no
   `matchMedia` listener, and no server persistence. `getTheme()` reads the DOM
   class, so the stored preference is lost. `useGridTheme.ts:21` already listens for
   an OS flip, but nothing ever changes the class, so that listener is dead code.
   **Breaks:** doc 16 Journey 16.1 (three-way segmented control Light · Dark ·

   follow).
   **Fix:** store `'light' | 'dark' | 'system'`, add a `matchMedia` listener, render
   a three-way segmented control in `UserMenu`, and `PATCH /api/me`.
   **Effort:** M

## What is already right

Worth protecting while the above is worked through.

- **No hardcoded hex and no Tailwind palette colour anywhere in `pages/` or
  `components/`.** Every colour reads a semantic token. The only hex in the tree is
  inside `grid/gridTheme.ts`, which parses token values for the canvas — that is
  reading a token, not writing a colour.
- **`grid/gridTheme.ts` is the model for the whole app.** One bridge, no colour
  literal, and `useGridTheme.ts` redraws the canvas on a theme flip.
- **`settings/WorkspacePhoneNumbers.tsx` is the reference table**: server-side page,
  sort, search, and filter, all in the URL, with a debounced search box, skeleton
  rows, `aria-sort`, a sticky header, and separate empty states for "no rows" and
  "no matches". Extract `DataTable` from this file, not from a blank page.
- **Destructive flows are done properly** in `Members_MemberRow.tsx`,
  `Members_PendingInvites.tsx`, and `PhoneNumbers.tsx`: `AlertDialog`, never
  `window.confirm`, the safe choice is the Cancel button, and the dialog states the
  consequence before the admin agrees to it.
- **`ui/alert-dialog.tsx:42-57`** handles the `<p>`-inside-`<p>` trap correctly with
  `asChild`.
- **Icon-only buttons carry `aria-label`** consistently across the app.
